A0. FOLD COUNT -- FIVE, NOT SIX
--------------------------------------------------------------------------------
  QUESTION  Section 5 said six folds and the table listed five. Which is it?

  ANSWER    FIVE.

  The config key was named walk_forward.n_folds but is the number of equal
  BLOCKS the history is cut into, not the number of folds. In
  xau_backtest/labeling/weights.py, expanding_folds() builds
  edges = linspace(0, n, n_blocks + 1) and then loops k = 1 .. n_blocks - 1.
  Fold k trains on blocks 0..k-1 and tests on block k. Block 0 is a training
  seed and is never a test window.

      SIX BLOCKS  ->  FIVE FOLDS

  The rev 1 prose was wrong; the rev 1 table was right.

  RENAMED 2026-09-14, before any results existed to be confused by it:
  n_folds -> n_blocks in configs/config.yaml, weights.py, the tests and
  scripts_label_report.py. Guarded by
  tests/test_labeling.py::test_n_blocks_is_blocks_not_folds, which asserts
  that b blocks produce b-1 folds for b in (4, 5, 6). See D4.

B.1  THE BREAKEVEN ARITHMETIC, FOR CROSS-REFERENCE          [DERIVED]
--------------------------------------------------------------------------------
  For stop S (ATR), target T (ATR), round-trip cost c (ATR):

      win  = T - c
      loss = S + c
      breakeven = (S + c) / ((T - c) + (S + c)) = (S + c) / (S + T)
      d(breakeven)/dc = 1 / (S + T)

  The cost CANCELS from the denominator. Sensitivity depends only on total
  barrier width -- and is monotonically decreasing in it, which is precisely
  why this argument cannot select a geometry (see A4).

  PRE-REGISTERED 4.0 / 6.0   (S+T = 10)   ->  10 pp per 1.0 ATR of cost

    cost regime                         c       R:R    breakeven
    ----------------------------------------------------------------
    2026, lowest observed            0.08     1.451       40.8%
    observed pooled (measured)       0.2002   1.380       42.0%
    full reversion, spread sticky    0.41     1.268       44.1%
    ----------------------------------------------------------------
    shift across the full observed range:                  3.3 pp

  REJECTED 1.0 / 1.5         (S+T = 2.5)  ->  40 pp per 1.0 ATR of cost

    cost regime                         c       R:R    breakeven
    ----------------------------------------------------------------
    2026, lowest observed            0.08     1.315       43.2%
    observed pooled                  0.2002   1.082       48.0%
    full reversion                   0.41     0.773       56.4%

    1. E_excess - 2.128 * SE > 0, with SE at the REALISED coverage.

C.1  WHAT THE MODEL PREDICTS
--------------------------------------------------------------------------------
  Two INDEPENDENT binary classifiers, one per side:

      long  model:  P(label_long_ret_atr_net  > 0)
      short model:  P(label_short_ret_atr_net > 0)

  JUSTIFICATION -- the target is BIMODAL, measured:        [COMPUTED]

    60.3% of labels resolve at a barrier and take one of two near-deterministic
    values, -4.0138 (stop) or +5.9857 (target), each with sd 0.0070. That sd is
    only the spread and slippage varying; the level IS the barrier.
    39.7% are time or rollover exits, continuously distributed at sd 1.78-2.05.

  So predicting the sign is, for three fifths of the sample, predicting which
  barrier gets hit. A regression on the return would be dominated by the two
  spikes and would spend its capacity fitting the barrier levels it already
  knows.

  REJECTED ALTERNATIVES
    three-class (long / short / flat)  -- forces a directional commitment at
        fit time and makes "take neither" a class rather than a threshold,
        which is where it belongs.
    regression on net return in ATR    -- see bimodality above.
    long-minus-short spread            -- assumes the sides are mirror images.
        They are not: the pessimistic resolver and the rollover truncation both
        bite asymmetrically, and the measured long/short gap is drift.

  DUAL-FIRE RULE -- TAKE NEITHER.

  When both side-models clear their thresholds on the same bar, NO POSITION is
  opened, and the frequency is reported per fold.

  The justification is measured, not stylistic.               [COMPUTED]
  Across 112,615 labelled bars:

    both sides net-positive         0    0.00%
    both sides net-negative    16,206   14.39%
    exactly one positive       96,409   85.61%

  ZERO bars have both sides net-positive. Mid-to-mid the two sides' gross
  returns are near-exact negatives, so their net returns sum to roughly -2c
  and cannot both clear zero. A dual fire therefore means AT LEAST ONE OF THE
  TWO MODELS IS WRONG, BY CONSTRUCTION. It is a disagreement signal, not an
  opportunity. Taking the higher probability, or the higher expected value,
  would be acting on a signal the data says is internally inconsistent.

  ENFORCED    docs/BACKTEST_DESIGN.md section 0.2j

--------------------------------------------------------------------------------
C.2  THE DECISION RULE -- SELECTED ON EXPECTANCY, NOT ON P(net>0)
--------------------------------------------------------------------------------
  CORRECTION  An earlier draft floored the threshold at the breakeven win rate
              (S + c)/(S + T) and made P(net > 0) the objective. That assumes
              outcomes are ONLY the two barriers. They are not:

                60.3% of labels sit on two near-deterministic barrier spikes
                39.7% exit at time or rollover, continuous, sd 1.78-2.05 ATR

              So P(net > 0) scores a +0.01 rollover exit identically to a
              +5.99 target hit. Maximising it is NOT maximising expectancy.

  OBJECTIVE   The threshold is selected on REALISED UNIQUENESS-WEIGHTED
              EXPECTANCY over the inner folds.

  SANITY      The breakeven floor (S + c_fold)/(S + T) is still computed and
  BOUND       reported per fold, using that fold's realised c. A selected
              threshold implying a win rate below its own fold's breakeven is
              a red flag that must be explained. It is REPORTED, never the
              objective.

  WINNER      For the trades the model takes AND wins, report the exit-reason
  COMPOSITION mix (target / stop / rollover / time), per fold. If wins are
              mostly small rollover exits rather than target hits, the barrier
              geometry is not doing the work and the reported expectancy rests
              on the continuous tail rather than on the trade thesis. That is
              a finding and is reported as one.

  ENFORCED    docs/BACKTEST_DESIGN.md section 0.2j

--------------------------------------------------------------------------------
C.3  FOLD STRUCTURE
--------------------------------------------------------------------------------
  OUTER   the 5 folds as built. Expanding, embargo 96 bars, purged by
          label_exit_index. Fold 0 excluded from the headline per 0.2g and
          reported in its own block.

  INNER   a 3-fold EXPANDING split of each outer training window, using the
          same purge and embargo machinery. ALL selection happens here:
          hyperparameters, feature selection, and the probability threshold.
          Nothing from an outer test window touches any of them.

--------------------------------------------------------------------------------
C.4  MODEL AND REGULARISATION
--------------------------------------------------------------------------------
  LightGBM, native null handling, NO complete-case filtering (0.2c).

  Sized against EFFECTIVE n, not row count (0.2e):

    max_depth            3
    num_leaves           <= 8
    min_child_samples    max(50, 0.05 * train_eff_n)
                           -> fold 0: 50 (floor binds)   fold 1: 72
                              fold 2: 109   fold 3: 146   fold 4: 181
    feature_fraction     0.5
    bagging              BY LABEL BLOCK, not by row, so overlapping labels do
                         not leak across the bag boundary
    lambda_l2            short inner-selected grid
    early stopping       inner split only
    sample_weight        uniqueness weights (materialised column)

--------------------------------------------------------------------------------
C.5  FEATURE SELECTION
--------------------------------------------------------------------------------
  Permutation importance on the inner validation split; keep top k, with k
  itself chosen on the inner split from a short grid.

  Importances are REPORTED per outer fold for inspection but NEVER POOLED
  across folds into a global ranking. Pooling reintroduces the leak through
  the back door.

--------------------------------------------------------------------------------
C.6  PER-FOLD REPORT -- MANDATORY, NO EXCEPTIONS
--------------------------------------------------------------------------------
  Every one of these, every fold:

    effective n, train and test                              (0.2e)
    realised round-trip cost c in ATR                        (0.2b, 0.2d)
    GROSS and NET expectancy in ATR                          (0.2b)
    THE ALWAYS-LONG FIGURE FOR THE SAME FOLD                 (0.2f)
    realised accuracy vs the fold's computed breakeven       (C.2)
    coverage: fraction of bars clearing the threshold
    decomposition by exit reason (target/stop/rollover/time) (A3)
    per-feature null rate, train and test                    (0.2g)
    phase-4 baselines on the same test window
    E_excess, per fold and pooled over folds 1-4             (0.2i)
    coverage, as a fraction of test bars                     (0.2i)
    the selected threshold AND the fold's breakeven bound    (0.2j)
    exit-reason mix of the model's WINNERS specifically      (0.2j)
    dual-fire frequency                                      (0.2j)

  HEADLINE RULE  the comparison is against the always-long figure, not against
                 zero, and fold 0 is not in the headline.

--------------------------------------------------------------------------------
C.7  GUARDS -- RUN BEFORE ANY RESULT IS BELIEVED
--------------------------------------------------------------------------------
  1. SHUFFLED-LABEL CONTROL. Same pipeline, labels permuted within fold. Must
     produce net expectancy indistinguishable from the cost drag. If it does
     not, the pipeline leaks.

  2. TIME-OF-DAY ABLATION. Refit without session_asian/london/overlap/ny,
     session_progress and mins_to_rollover. The min_bars mask cut the
     MECHANISM behind the time-of-day conditioning but not necessarily the
     CORRELATION. If performance collapses without them, the model is trading
     the session clock, not the market.

  3. COST-REGIME SPLIT. Report folds grouped by high-cost and low-cost era so
     the 5x cost decline cannot masquerade as improving edge.

  4. GEOMETRY ROBUSTNESS. Re-run at 3.0/4.5 and 6.0/9.0. REPORTED, never
     selected on. An edge present only at 4/6 is diagnostic of overfitting
     (0.2h).
